# Плагин prorab-tech

Ветка **тех-качества** prorab — отдельный неймспейс, чтобы не путать с продуктовыми
командами (`/prorab:*`). Про непрерывное оздоровление кода: находить накопленный техдолг
и **безопасно** его чинить, не меняя поведение. Внутри — **две пары** команд под две
разные природы долга:

- **Структурный долг** (дублирование, сложность, слои) — `audit` → `refactor`.
- **Статический долг** (линтеры, типы, форматтеры, мёртвый код, гейты) — `lint-audit` → `lint-fix`.

## Пара структурного качества: `audit` → `refactor`

- **`/prorab-tech:audit`** (`commands/audit.md`) — многоагентный аудит кодовой базы:
  сканирует по классам смеллов (дублирование, сложность, нарушения слоёв, мёртвый код,
  надёжность, перф, покрытие, конвенции) + churn×complexity по git, кластеризует,
  ранжирует по `польза × безопасность × объём × уверенность`, состязательно верифицирует
  топ и выдаёт **оптимального кандидата**. Кода не трогает. Результат —
  `tasks/audits/AUDIT-<slug>.md` (бэклог + полная спека #1).
- **`/prorab-tech:refactor`** (`commands/refactor.md`) — безопасная починка под ключ через
  мультиагентный ultracode-Workflow. **Prime directive — сохранение поведения:** сеть
  характеризационных тестов на старом коде, мелкие шаги, состязательный поиск дрейфа,
  дифференциальный прогон old-vs-new, измеренное улучшение качества. Оба режима:
  `refactor <id>` чинит выбранного кандидата, `refactor` без аргумента — auto-pick #1 из
  свежего аудита. Результат — код + `tasks/IMPL-refactor-<slug>.md`.

Конвейер: `audit → AUDIT → refactor → IMPL → /prorab:announce`.

## Пара статического качества: `lint-audit` → `lint-fix`

Про тулинг: линтеры, тайпчекеры, форматтеры, мёртвый код, безопасность и **гейты**
(pre-commit/CI). Ключевая идея — **храповик**: статический долг монотонно фиксируется —
включил правило, свёл нарушения к нулю, **запер гейтом** → уровень не откатится. Поэтому
результат — не «один кандидат», а **упорядоченная лестница безопасных проходов**, каждый из
которых поднимает пол И запирает его.

- **`/prorab-tech:lint-audit`** (`commands/lint-audit.md`) — инвентаризирует тулинг (что
  есть / сломано / отсутствует) + прогоняет все доступные анализаторы (read-only), для
  отсутствующих оценивает «стоимость включения» на щадящей планке. Кластеризует находки в
  батчи и упорядочивает лестницей: **A** нулевой-риск автофикс → **B** провод/починка
  инструментов на проходящей базе → **C** гейт на текущем уровне (высший рычаг) → **D**
  инкрементальный ратчет строгости. Скоринг `польза × безопасность × объём × уверенность` +
  DAG пред-условий; состязательно верифицирует, что каждый батч behavior-preserving и
  проходим за один заход. Кода не трогает. Результат — `tasks/audits/LINT-<slug>.md`
  (инвентарь тулинга + роадмап батчей + полная спека батча #1).
- **`/prorab-tech:lint-fix`** (`commands/lint-fix.md`) — выполняет **ОДИН** батч под ключ
  через Workflow. **Prime directive — сохранение поведения + запертый храповик:** снять
  конечный класс нарушений, доказать эквивалентность (baseline-сеть тестов/сборки/тайпчека +
  поиск дрейфа), **добавить гейт и sabotage-пробой доказать, что он ловит регресс**.
  Латентный баг, вскрытый анализатором, **не чинит** (это смена поведения → роут в
  `/prorab:refine`→`/prorab:build`). Уважает порядок лестницы (не берёт батч раньше
  пред-условий). Оба режима: `lint-fix <id>` — конкретный батч, `lint-fix` без аргумента —
  auto-pick первый несделанный батч с выполненными пред-условиями. Результат — код + гейт +
  `tasks/IMPL-lint-<slug>.md`; отмечает батч done в плане.

Конвейер: `lint-audit → LINT → lint-fix → (повторять по батчам) → /prorab:announce`.
Каждый вызов `lint-fix` = одна ступень храповика; запускай его повторно, пока лестница не
пройдена. Команды глобальны, артефакты локальны для проекта.

**Инверсия к `build`:** `/prorab:build` доказывает, что *новое* поведение соответствует
требованию; `/prorab-tech:refactor` доказывает, что *старое* поведение **не изменилось**.
Разная дисциплина верификации — поэтому отдельный исполнитель, а не прогон через `build`.

Установка и обновление описаны в [корневом README](../../README.md).
