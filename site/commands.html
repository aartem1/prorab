Reference

Ten commands.

Six on the product track, four on the tech-quality track. Each one states what it takes, what it writes, and — the part that usually matters more — what it refuses to do and where it hands the task over instead.

Before the reference

Picking a lane

Four questions decide which command you want. You do not have to answer them correctly — quick re-checks its own eligibility after reading the code and hands over rather than finishing a large change on a small budget, and refine points at quick when a settled idea turns out to be tiny.

The situationReach for
The requirement can be read more than one way, touches an external contract, or spans layers/prorab:refine → /prorab:build
One or two files, one layer, nothing published changes, and you can already state given → expected/prorab:quick
Something shipped and you want to know whether it works for the people who use it/prorab:verify
The structure is wrong but the behavior must not change/prorab-tech:audit → /prorab-tech:refactor
Linters, types and formatters are unenforced or in disarray/prorab-tech:lint-audit → /prorab-tech:lint-fix
You need to tell someone what changed, or find out what happened here before/prorab:announce · /prorab:ask

Product track · prorab

From an unclear idea to a message you can forward.

Four stages plus two you reach for as needed. verify is optional and works on any scope — after build, after quick, or on a branch nobody used the framework for.

/prorab:refine writes no code

Your sparring partner while the idea is still raw. It reads the relevant code first, then interrogates the idea — contradictions, gaps that decide scope, assumptions it had to invent to make the idea coherent — until a spec and an implementation plan can be written meaningfully. Questions come one to four at a time with specific, mutually exclusive options, never as a wall of fifteen.

Takes
A short idea description. Raw, incomplete or self-contradictory is the expected input, not a problem.
Writes
tasks/ideas/IDEA-<slug>.md — problem, solution, scope IN/OUT, affected parts and reuse points, order of stages, key decisions including what was rejected and why, risk spikes, remaining assumptions, and a numbered Definition of Done. Plus a Code map handoff: every file it opened with a content hash, reuse and change points, contracts at risk, conventions to mirror, and an honest list of what it did not study.
Budget
Dialogue-first: no Workflow, at most two delegated Explore contexts for a genuinely cross-cutting idea. After one delegated round with no new scope-relevant fact, it stops delegating.
Refuses
To write or change any project code. To declare the idea ready — you confirm that, it may only propose it. To agree for the sake of agreeing: if the idea looks harmful it says so with arguments and offers alternatives.
Notable
An unresolved fork becomes [?: …] in the artifact rather than a silent default, and build treats that marker as a blocker. Skepticism is bounded on purpose: it serves scope and DoD, and after two rounds that move nothing it proposes settling.
Then
/clear, then /prorab:build <slug> — a fresh context that pays nothing for the dialogue and re-uses the hashed Code map instead.

/prorab:build turnkey

Implements a refined idea end to end through a multi-agent Workflow: recon → plan → DAG-ordered implementation → adversarial review → verification. There is no approval gate in the middle and it will not ask whether to continue; in place of human approval, quality rests on independent verification and the project’s own full check run.

Takes
A path to tasks/ideas/IDEA-*.md, an idea slug, or a free description of an already-refined idea. Without an IDEA it warns that quality will suffer and suggests refining first.
Writes
Working code plus tasks/IMPL-<slug>.md: the task DAG, the per-file change list, the test plan, the verification recipe, the decisions and deviations, and a DoD table with a proof column. Archives the completed bundle into tasks/archive/<YYYY>/ — only after verification passed.
Stops on
A real blocker only: a failed risk spike, an unclosed [?: …], a direct contradiction between the IDEA and the code, an IDEA defect affecting scope or DoD, or a secret/access it does not have. A “sensible default” is allowed only for decisions that touch neither scope nor DoD.
Refuses
To re-open product decisions already settled in the IDEA. To take an expected value from its own output. To green up a test — assert True, a tautology, skip/xfail, mocking the unit under test, a hardcoded answer for the test input. To declare done without a run. To commit or push unasked.
Notable
Reuses the IDEA’s Code map where the recorded hashes still match. Derives the verification recipe from repository guidance, CI and task runners rather than assuming a stack — a missing command is reported as a gap, not invented. Records which of its tests were proven able to fail, so verify does not re-prove them.

/prorab:quick 2 contexts, fixed

The cheap lane. No IDEA, no IMPL, no archive, no Workflow — on a two-file edit that ceremony costs more than the work. What is not dropped: a Definition of Done stated in chat before the code exists, a test that fails for the right reason first, the project’s own checks, the documentation duty, and one independent verifier.

Takes
A concrete small change — one or two files, one layer, no external contract touched.
Writes
Code plus one compact tasks/quick/QUICK-<slug>.md: what changed and why, the DoD table with its proof column, the exact checks and their results, the documentation it corrected, and the verifier’s verdict. If it needs more than about a screen to state honestly, the task was not small.
Escalates
Mandatory, not a preference, and it applies mid-run: an external contract, more than two or three files, two incompatible readings, security/auth/payment/permission logic, a behavior-preserving restructure, or missing access. It stops, names the trigger, and points at /prorab:refine or the tech track — leaving a record marked escalated if it had already edited files.
Refuses
To run a Workflow or a judge panel, to create IDEA/IMPL files, to archive anything, or to “just finish it since I’m already here”.

/prorab:verify black box

Establishes whether shipped functionality actually works for the people who use it — someone in a UI, an API client, a CLI user, a reader of an export, an operator watching the output. The probing context is blind by construction: delegated at every tier including the cheapest, given a charter of surfaces and expected results, and never the implementation, the diff or a path.

Takes
A slug, an IMPL/QUICK path, a branch or base ref, a commit range, uncommitted, or a free description. Empty derives the scope from git and asks only when it is genuinely undetermined — with concrete candidates, never a vague “what should I check?”.
Writes
tasks/verify/VERIFY-<slug>.md — a graded verdict and evidence per behavior, the defects with their reproductions and routing, the coverage table, the check digests, and what stayed unverified — plus the missing tests, each proven by a mutation in an isolated worktree. Archives nothing.
Verdicts
works · broken (the expected result is not produced at all) · differs (it works, but not as the requirement states) · unverifiable (the surface, data, access or oracle could not be obtained), each with a grade: observed (drove the real surface) or proxy (drove it through the project’s own harness).
Refuses
To fix anything — the only code it writes is test code, and defects are routed with their reproduction to quick, build or refactor. To accept a works that rests on the system’s own output, on “no error”, or on a screenshot with no compared value. To probe production with anything but observation, to enter credentials anywhere, to install into the project, or to fetch a runner without asking first.
Notable
differs is not automatically a defect: it may mean stale code or a stale requirement, so it names which reading the evidence supports and leaves the product call to you. A web UI is driven headless by default; pixels are reserved for genuinely perceptual cases and an interactive visual session is an escalation whose trigger is logged.

/prorab:announce writes no code

A short, precise announcement of the result, dense enough to forward in a messenger. The recipient should understand in 20–30 seconds what was done, what is new, what changed and how it is computed, without reading code. It reads the IMPL, the diff and the IDEA — and takes “done” from what landed, not from what was intended.

Takes
A feature slug, a path to an IMPL or IDEA, commits, or a free “what we shipped”. Empty means the latest completed work.
Writes
The text in chat, ready to copy-paste. It saves ANNOUNCE-<slug>.md only on request, and for an already-archived task into that same archive directory.
Budget
Read-only and S-sized: no Workflow, at most one delegated context total, at most one adversarial fact-check pass.
Refuses
To write about anything unverified or not actually done. To treat a partial or blocked IMPL as completed. To invent a computation method — it takes methods and thresholds from the IDEA/IMPL, or asks. To recreate an active IDEA or IMPL for work that is already archived. To commit.
Notable
Terms are taken strictly as they appear in the app’s own UI, and a known limitation the recipient should hear about goes in without being inflated.

/prorab:ask read-mostly

Answers a question about the project or its history: how a component works, why an approach was chosen, where a value is computed, which consumers a contract has, what was already verified. It finds the area through project memory and task artifacts, then checks every material claim against current code, docs or git history — and cites the sources.

Takes
A question about architecture, behavior, history, consumers, ownership or verification.
Writes
Nothing, except that a memory entry its own read-only investigation disproved may be corrected or marked stale.
Refuses
To answer a current-state question from memory or an archived artifact alone. To present an inferred historical motive as documented fact. To implement a fix, run a mutating check, install anything, commit or push.
Notable
The answer separates Confirmed now from Historical context and Unverified, so a fact from an old artifact is never handed to you as current truth.

Tech-quality track · prorab-tech

Two pairs, for two natures of debt.

Structural (audit → refactor) and static (lint-audit → lint-fix). Both executors carry the same prime directive, and it is the opposite of build’s: prove that old behavior did not change. Their results are announced by the same /prorab:announce.

/prorab-tech:audit touches no code

A multi-agent audit of structure. It sweeps three grouped directions — structure, reliability and security, performance and maintainability — and adds churn×complexity from git history, on the principle that code which is changed often and is also complex is where refactoring pays. Findings are clustered, ranked, and the top one is adversarially verified.

Takes
Empty for the whole project, or a focus: a path, a subsystem, or a problem class such as “duplication in services”.
Writes
tasks/audits/AUDIT-<slug>.md — a ranked backlog plus one fully specified candidate, including what to add as a characterization net before the refactoring. Stamped with hashed provenance: the commit plus hashes of the target files, the tests its coverage claim rests on, and the call-site files.
Ranks by
value × safety × size × confidence — high value at high safety and bounded size wins, and on a tie the safer, more isolated candidate does. A refactoring that is valuable but unsafe is not the one to do first.
Refuses
To change any code, and to call something a finding on taste alone: a diagnosis rests on executable, measured or analyzer evidence.
Then
/clear, then /prorab-tech:refactor.

/prorab-tech:refactor turnkey

A turnkey safe fix via a multi-agent Workflow. Prime directive — behavior preservation: the same outputs on the same inputs, the same side effects, the same errors, the same contracts. Bugs and quirks are preserved too — this command does not “fix” them along the way.

Takes
Empty auto-picks candidate #1 from the latest AUDIT; or an id/slug, a file path, or a free problem description.
Writes
Code plus tasks/IMPL-refactor-<slug>.md, reporting two blocks: behavior preserved (net, differential/mutation evidence, stable contracts, zero scope creep) and quality improved (a numeric before→after metric).
Floor
No net, no refactoring. If the target has no coverage, characterization tests pinning the current behavior are written first and must be green on the OLD code. Then a contract diff, an adversarial drift search, and at least one differential old-versus-new run — none of which any budget tier can switch off.
Refuses
To start without a net that can catch a behavior change. To accept equivalence as the default — behavior counts as changed until proven otherwise, and any diverging input is a critical finding. To widen scope into a behavior fix.
Notable
It re-hashes the AUDIT’s provenance before choosing a tier, because it would otherwise inherit safety and blast-radius numbers from an audit describing code that has moved on. A stale target makes the candidate obsolete until the smell is re-confirmed; a stale test voids the coverage claim; a stale call site voids the blast radius.

/prorab-tech:lint-audit touches no code

An audit of statics. It inventories the tooling — present, broken or absent — runs the analyzers the project already has, read-only, and labels estimates for absent tools as manual guesses rather than measurements. A tool that is not installed is not silently installed to produce a number.

Takes
Empty for the whole project, or a focus: a tool, a subsystem, or a rule class.
Writes
tasks/audits/LINT-<slug>.md: an ordered ladder of safe single-pass batches — A autofix → B onboard tools on a passing base → C create the first gate → D strictness ratchet — plus the exact invocations and the gate entrypoint.
Notable
A batch is defined as work that is verifiably green in one pass and independently shippable. “Fix all typing” is not a batch; “enable the typechecker at bar X for module Y and drive N errors to zero” is. Violation counts in the plan are explicitly a snapshot, not a handoff — they go stale the moment a batch lands, and re-running an analyzer is nearly free.
Refuses
To change code, to simulate a dry run for a tool that is not there, or to promise a locked ratchet before a gate exists.

/prorab-tech:lint-fix one batch per run

Runs exactly one rung of that ladder, turnkey, with a truthful gate lifecycle: batches before C are preparatory and are never described as locked, C creates the first gate and sabotage-proves it, and later batches tighten or expand that same gate and prove the changed coverage rather than adding a second ad-hoc one.

Takes
Empty auto-picks the first undone batch whose prerequisites are met; or a batch id/slug, a path to the LINT file, or a free description.
Writes
Code, gate-state evidence, and tasks/IMPL-lint-<plan-slug>-batch-<id>.md. The LINT and its batch artifacts are archived together once the ladder is complete or explicitly closed — never a partial ladder.
Refuses
To change runtime behavior: static-quality edits keep the same outputs, side effects and contracts. A latent bug the analyzer surfaces — a dead branch, an unreachable path, a swallowed exception — is routed to the product track, not quietly fixed inside a pass that claims to change nothing.
Notable
It reads the current gate state from the last completed batch artifact rather than rediscovering it, and treats a falsely-safe autofix — a removed export that was called dynamically — as costing more than an unfixed warning.

Overrides

Flags

Every heavy command triages its own complexity. When you already know better, you can pin the choice — the human beats the auto-triage — but no flag removes the safety floor or the 16-context ceiling.

FlagEffect
--tier=S|M|LPins the context tier: 2, 6 or 12 contexts cumulative for the whole command.
--fastThe cheapest defensible tier, and the economy verification profile where its conditions hold.
--thoroughAllows expansion to the absolute ceiling of 16 contexts, and the thorough profile.
--verification=economy|balanced|thoroughMutation intensity, controlled separately from the tier: none · one per critical cluster (default) · one per substantial boundary.

A natural-language request in the arguments does the same thing. Whatever is chosen — tier, profile, used/cap, escalation reason, and anything consciously skipped — is logged rather than left implicit.

Language

Command bodies and everything internal run in English — the reasoning, the prompts between agents, the schema outputs. It is denser in tokens and steadier in quality. Everything a human reads is in the task’s language, detected from how you phrased the request and Russian by default: the chat, the refine dialogue, the announcement, and the artifacts, which stay project documents in that language. Code, identifiers, comments and commit messages are always English; user-visible domain and UI terms are carried verbatim, never round-tripped through a double translation.
