Product track · prorab

From an unclear idea to a message you can forward.

Four stages plus two you reach for as needed. verify is optional and works on any scope — after build, after quick, or on a branch nobody used the framework for.

/prorab:refine writes no code

Your sparring partner while the idea is still raw. It asks skeptical questions, reads the relevant code, and surfaces contradictions, hidden assumptions and gaps until a spec and an implementation plan can be written meaningfully.

Takes
A short idea description — raw, incomplete or contradictory is fine.
Writes
tasks/ideas/IDEA-<slug>.md, including a Code map handoff: every file it opened with a content hash, reuse and change points, contracts at risk, conventions to mirror, and an honest list of what it did not study.
Budget
At most two Explore contexts.
Then
/clear, then /prorab:build <slug> — a fresh context that pays nothing for the dialogue.

/prorab:build turnkey

Implements a refined idea end to end through a multi-agent Workflow: recon → plan → DAG-ordered implementation → adversarial review → verification. There is no approval gate in the middle; the agents check each other.

Takes
A path to tasks/ideas/IDEA-*.md, an idea slug, or a free description of an already-refined idea.
Writes
Working code plus tasks/IMPL-<slug>.md. Archives the completed bundle into tasks/archive/<YYYY>/ once verification passed — never on a partial result.
Notable
Reuses the IDEA's Code map where the recorded hashes still match, so recon isn't paid for twice. Derives the verification recipe from repo guidance, CI and task runners rather than assuming a stack. Records which of its tests were proven able to fail, so verify doesn't re-prove them.

/prorab:quick 2 contexts, fixed

The cheap lane. No IDEA, no IMPL, no archive, no Workflow — on a two-file edit that ceremony costs more than the work. What is not dropped: a Definition of Done stated before the code exists, a test that fails for the right reason first, the project's own checks, and one independent verifier.

Takes
A concrete small change — 1–2 files, one layer, no external contract touched.
Writes
Code plus one compact tasks/quick/QUICK-<slug>.md: what changed and why, the DoD table, the exact checks and their results, and the verifier's verdict.
Escalates
It re-checks its eligibility gate after reading the code. If the task isn't small it hands over to /prorab:refine or /prorab-tech:refactor rather than finishing on the wrong budget — and still leaves a record marked escalated if it had already edited files.

/prorab:verify black box

Establishes whether shipped functionality actually works for the people who use it — someone in a UI, an API client, a CLI user, a reader of an export. The probing context is blind by construction: delegated at every tier, given a charter of surfaces and expected results, and never the implementation, the diff or a path.

Takes
A slug, an IMPL/QUICK path, a branch or base ref, a commit range, uncommitted, or a free description. Empty derives the scope from git and asks only when it is genuinely undetermined.
Writes
tasks/verify/VERIFY-<slug>.md — a graded verdict and evidence per behavior — plus the missing tests, each proven by a mutation in an isolated worktree. Archives nothing.
Refuses
To fix anything. The only code it writes is test code; defects are routed with their reproduction to quick, build or refactor.
Notable
The oracle comes from the requirement, never the system's own output — a works resting on what the system printed is downgraded, not accepted. A web UI is driven headless by default: the prober authors one consumer session and judges a structured result, with pixels reserved for genuinely perceptual cases and an interactive visual session only on a named, logged trigger.

/prorab:announce writes no code

A short, precise announcement of the result, dense enough to forward in a messenger. The recipient should understand in 20–30 seconds what was done, what's new, what changed and how it's computed, without reading code. It reads the IMPL, the diff and the IDEA, and fact-checks against them.

Takes
A feature slug, a path to an IMPL or IDEA, commits, or a free "what we shipped". Empty means the latest work.
Writes
The text in chat. It saves ANNOUNCE-<slug>.md only when the task is already archived, into that same archive directory.
Refuses
To commit, and to recreate an active IDEA or IMPL for work that is already done.

/prorab:ask writes no code

Answers a question about the project or its history: how a component works, why a decision was made, who consumes a contract, what was already verified. It finds the area via project memory and task artifacts, then verifies every material claim against current code, docs or git history — and cites the sources.

Takes
A question about architecture, behavior, history, consumers, ownership or verification.
Writes
Nothing, except that a disproved memory entry may be corrected or marked stale.
Notable
It separates Confirmed now from Historical context, so a fact from an old artifact is never handed to you as current truth.

Tech-quality track · prorab-tech

Two pairs, for two natures of debt.

Structural (audit → refactor) and static (lint-audit → lint-fix). Both executors share one prime directive: behavior preservation. Their results are announced by the same /prorab:announce.

/prorab-tech:audit touches no code

A multi-agent audit of structure. It sweeps by smell class plus churn×complexity from git, clusters the findings, ranks them by value × safety × size × confidence, and adversarially verifies the top one. The output is the single best candidate for a safe refactoring, plus a ranked backlog of the rest.

Takes
Empty for the whole project, or a focus — a path, a subsystem, or a problem class such as "duplication in services".
Writes
tasks/audits/AUDIT-<slug>.md, stamped with hashed provenance: the commit plus hashes of the target files, the tests its coverage claim rests on, and the call-site files.
Then
/clear, then /prorab-tech:refactor.

/prorab-tech:refactor turnkey

A turnkey safe fix via a multi-agent Workflow. Prime directive — behavior preservation: characterization tests over the old code, small steps, an adversarial drift search, a differential old-vs-new run, and a measured quality improvement.

Takes
Empty auto-picks candidate #1 from the latest AUDIT; or an id/slug, a file path, or a free problem description.
Writes
Code plus tasks/IMPL-refactor-<slug>.md.
Notable
It re-hashes the AUDIT's provenance before choosing a tier, because it otherwise inherits safety and blast-radius numbers from an audit that may describe code which no longer exists. A stale target makes the candidate obsolete until the smell is re-confirmed; a stale test voids the coverage claim.

/prorab-tech:lint-audit touches no code

An audit of statics. It inventories the tooling — present, broken or absent — runs the analyzers the project already has, read-only, and labels absent-tool estimates as manual guesses rather than measurements.

Takes
Empty for the whole project, or a focus — a tool, a subsystem, or a rule class.
Writes
tasks/audits/LINT-<slug>.md: an ordered ladder of safe passes — A autofix → B onboard tools → C first gate → D strictness ratchet — plus the exact invocations and the gate entrypoint.
Notable
Violation counts in it are explicitly a snapshot, not a handoff: they go stale the moment a batch lands, and re-running an analyzer is deterministic and nearly free.

/prorab-tech:lint-fix one batch per run

Runs exactly one pass from that ladder, turnkey. Behavior preservation plus a truthful gate lifecycle: batches before C are preparatory and are not called locked, C creates and sabotage-proves the first gate, and later batches tighten or expand it and prove the changed coverage.

Takes
Empty auto-picks the first undone batch whose prerequisites are met; or a batch id/slug, a path to the LINT file, or a free description.
Writes
Code, gate-state evidence, and tasks/IMPL-lint-<plan-slug>-batch-<id>.md. The LINT and its batch artifacts are archived together once the ladder is complete or explicitly closed — never a partial ladder.
Notable
A latent bug found on the way is routed to the product track, not silently fixed inside a pass that claims to change no behavior.

Language

Command bodies and everything internal run in English — reasoning, inter-agent prompts, schema outputs. It is denser in tokens and steadier in quality. Everything a human reads is in the task's language, detected from how you phrased the request: the chat, the refine dialogue, the announcement, and the artifacts, which stay project documents in that language. Code, names, comments and commit messages are always English; user-visible domain and UI terms are carried as-is, never round-tripped through a double translation.
