Why it exists

Agent work breaks in two places.

The idea goes in half-formed and you get a confident implementation of the wrong thing — or the agent burns an enormous number of tokens re-reading the same files with no upper bound. Prorab is a fix for both, and refuses to trade one for the other.

01 / floor

A quality floor you can't skip

A Definition of Done written before any edit. A test that failed for the right reason first. An independent reviewer that never wrote the code. Documentation the change falsified, corrected in the same pass — a stale doc is an incomplete change, not a follow-up.

02 / ceiling

A budget it can't exceed

Every heavy command triages complexity first and picks a tier. The count is cumulative for the whole command, retries included, and enforced in the generated Workflow script — not promised in prose.

The ceiling, moved

Pick a tier. Watch the contexts.

Complexity is estimated from cheap signals — size, blast radius, novelty, reversibility, uncertainty — and the tier follows. You can pin it with --fast, --thorough or --tier=S|M|L; the 16-context ceiling stays absolute.

6 / 16 contexts
spent by this command reachable only on confirmed critical risk

A tier bounds how many contexts open, not how full each one gets. So a second, orthogonal limit applies at every tier: raw suite output never enters a context — it goes to a file outside the working tree and comes back as a ~40-line digest — and a delegated context returns a capsule of claims and path:line pointers, never the material itself. Compaction may shorten what failed, never conceal that something failed.

The path

Two tracks, one discipline.

The product track proves that new behavior matches a requirement. The tech track proves that old behavior did not change. Different proofs, so different executors — and one shared floor. Pick a stage.

Install

Three lines, inside Claude Code.

Both plugins live in the same marketplace but install separately — take one track or both. 

/plugin marketplace add aartem1/prorab
/plugin install prorab@prorab
/plugin install prorab-tech@prorab

Update later with /plugin marketplace update prorab. Developing the framework itself? Point the marketplace at a local clone: /plugin marketplace add /path/to/prorab.

Then run your first task

/prorab:refine  add a CSV export to the reports page
→ questions, code study, contradictions — and IDEA-csv-export.md. No code.

/clear
/prorab:build
→ recon reused from the hashed Code map, then implemented and reviewed.

/prorab:verify
→ probed from outside by a context that never read the diff.

Reference

Which command do I need?

refine → build for anything touching an external contract, spanning layers, or readable more than one way. quick for the daily two-file change. You don't have to guess right — each one re-checks and hands over.

/prorab:refineThink an idea through before anyone writes code /prorab:buildImplement a refined idea, end to end /prorab:quickMake a small everyday change (1–2 files) /prorab:verifyCheck it actually works for its users /prorab:announceTell the team what shipped /prorab:askAsk about this project or its history /prorab-tech:auditFind the debt worth paying down first /prorab-tech:refactorPay it down without changing behavior /prorab-tech:lint-auditGet linters and types under control /prorab-tech:lint-fixLand one safe static-quality pass

What lands in your project

The commands are global. The evidence is yours.

Commands install once and update from git. Everything they write is local to the working project and worth committing — these files are the record of what was decided and why. 

tasks/
├── ideas/IDEA-<slug>.md                     # refine
├── IMPL-<slug>.md                           # build
├── quick/QUICK-<slug>.md                    # quick
├── verify/VERIFY-<slug>.md                  # verify
├── audits/AUDIT-<slug>.md                   # audit
├── audits/LINT-<slug>.md                    # lint-audit
├── IMPL-refactor-<slug>.md                  # refactor
├── IMPL-lint-<plan-slug>-batch-<id>.md      # lint-fix
├── memory/                                  # small, verified project memory
└── archive/<YYYY>/<task-slug>/              # completed, verified bundles
